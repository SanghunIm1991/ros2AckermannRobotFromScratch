# 学習計画（ROS 2 と Gazebo で、アッカーマン式の台車をゼロから組み立てる）

[`dev/idea_origin.md`](../dev/idea_origin.md) の段階を学習の順番に並べ、各フェーズの内容・前提・完了条件をまとめたもの。ゴールと技術を選んだ理由は構想の文書に、決めた経緯は [`dev/qa_log.md`](../dev/qa_log.md) にある。

> **作成中である。** フェーズの並びと必須・任意・発展の分け方は、たたき台である。各フェーズの手順書の分け方・前提・完了条件の数値は案で、手順書を作るときに、使い捨ての環境で確かめて直す。台車の寸法は、ホイールベース 0.20 m・トレッド 0.16 m・車輪の半径 0.04 m・舵の角度の上限 0.6 rad に決めた（2026-11-08）。

## 1. 目的とゴール

- **目的**: アッカーマン式の台車が、指令を受けてから自律で目的地へ着くまでの仕組みを、部品ごとに自分で組み立てながら理解する。
- **ゴール**: フェーズ6。Gazebo の中の台車が、フェーズ5で作った地図の上で、Nav2 によって目的地まで自律で移動する。

## 3. フェーズ計画

各フェーズの完了条件を満たしてから次へ進む。所要の目安は、手順書を作るときに見積もる。

### フェーズ0: アッカーマン式の台車と、自律の移動の全体の構成（読み物）

- **内容**: アッカーマン式の台車とは何か（前輪で舵を切り、後輪で進む。その場で回れない）。差動二輪の台車との違い（アッカーマンを理解するのに要る範囲に限る）。自律で移動する台車の部品（模型・駆動・オドメトリ・センサ・地図・計画と追従）と、それぞれをどのフェーズで作るか。ROS 2 の基礎の語（ノード・トピック・TF 等）は、初出で1文ずつ説明し、詳しくは親プロジェクトの手順書へリンクする。
- **完了条件**: 次の問いに答えられる。アッカーマン式の台車が `v`＝0 で `ω`≠0 の指令を実現できないのはなぜか。自律の移動に要る部品を5つ挙げ、それぞれが何を受け取り何を出すか。

### 環境構築

- **内容**: WSL2・Ubuntu 24.04・ROS 2 Jazzy の導入は、詳しい説明を親プロジェクトの [環境構築の手順書](https://github.com/SanghunIm1991/ros2MinimalPhysicalAi/blob/main/docs/setup_wsl2_ros2.md) に任せ、この教材の手順書には最低限の実行の手順（コマンドと期待する結果）だけを載せる。Gazebo（`ros-jazzy-ros-gz`）の導入と確かめ方は、この教材の手順書で書く。Nav2 と `slam_toolbox` は、使うフェーズで導入する。
- **完了条件**: `gz sim --version` が Harmonic の版（8.x）を表示し、`ros2 pkg list` に `ros_gz_sim` と `ros_gz_bridge` が出る。

### フェーズ1: URDF の台車

- **内容**: 1-1で、台車の本体・後の2輪（回る関節）・前の2輪（舵を切る関節と回る関節）を URDF（xacro）で書き、`robot_state_publisher` と RViz2 で形と TF の木を見る。1-2で、慣性と衝突の形を足して Gazebo に出し、関節を個別に動かすプラグイン（舵は角度を指令する `JointPositionController` を、関節を速さで動かす設定（`use_velocity_commands`）で使い、後輪は速さの指令の `JointController`）を付けて、`ros_gz_bridge` で ROS 2 から指令を送り、舵と車輪が指令どおりに動くことを確かめる（駆動の方法は、予備の実験で決めた。2026-11-08）。寸法は、この教材で決めた値を使う。
- **前提**: 環境構築、フェーズ0。親プロジェクトのフェーズ2（ワークスペースとパッケージ）の2-1・2-2・2-4・2-5節と、フェーズ4（launch）の4-1節（1-1で決めた。1-2も同じ節で足りる。2026-11-11）。
- **完了条件（案）**: 1-1は、`check_urdf` が通り、`tf2_echo` で見た前輪の位置が、決めたホイールベースとトレッドの半分に一致する（1 mm 以内）。1-2は、Gazebo の中で台車が倒れずに静止し、舵の関節に与えた角度に誤差0.01 rad 以内で達し（作成時に測った到達の時間は0.2秒以下）、後輪に同じ速さを指令すると、横のずれ0.01 m 以内でまっすぐ進む（2026-11-11、1-2の手順書を作るときに決めた）。

### フェーズ2: アッカーマンの運動学

- **内容**: 2-1で、`cmd_vel` の `v`（前に進む速さ）・`ω`（向きを変える速さ）から、曲率 κ=ω/v を経て、左右の舵の角度と左右の後輪の速さ（回転の速さ）を求める計算（自転車モデルの舵の角度 δ=atan(L·ω/v) は、左右の舵の角度の間の値になる。L はホイールベース）を、ROS 2 を使わないクラスで書き、値を確かめる。左右の前輪の舵の角度の違い（アッカーマンの幾何）と、最小の回転半径も扱う（舵の上限 δ_max は左右の舵の関節それぞれにかけるので、先に上限に当たるのは内側の舵で、後車軸の中心の最小の回転半径は L/tan(δ_max) + W/2 になる。W はトレッド。この教材の台車では約 0.37 m）。`v`＝0 や、最小の回転半径より小さく曲がる指令の扱いも、2-1で決めてクラスに書く（2-1の手順書を作るときに、`v`＝0 は止まって舵をまっすぐにし、小さく曲がる指令は曲率を上限で切って `v` を保つ形にした。2026-11-11）。2-2で、そのクラスをノードで包み、`cmd_vel` を受けて関節に指令を出し、台車を円を描いて走らせる。
- **前提**: フェーズ1。親プロジェクトのフェーズ3-1（Publisher / Subscriber）のうち、使う節。
- **完了条件（案）**: 2-1は、決めた入力の組（直進・左右の旋回・`v`＝0・上限を超える `ω`・後退）に対して、クラスの出力が手計算の値と 1e-6 以内で一致する（後退は、2-1の手順書を作るときに足した。2026-11-11）。2-2は、一定の `v`・`ω` で走らせたときの円の半径（Gazebo の中の真の位置から求める）が、`v/ω` と5%以内で一致する（2-2の手順書を作るときに、上限を超える `ω` では、半径が最小の回転半径と5%以内で一致することも足した。真の位置は、Gazebo の `OdometryPublisher` で出し、`/ground_truth/odom` として中継する。2026-11-14）。

### フェーズ3: 自転車モデルのオドメトリと TF

- **内容**: 後輪の回転の速さと舵の角度（関節の状態）から、自転車モデルで台車の位置と向きを積算するノードを書き、`nav_msgs/Odometry` と `odom → base_footprint` の TF を出す（3-1。TF の子のフレームは、模型の根元の `base_footprint` にした。2026-11-14）。積算の誤差がどう溜まるかを、Gazebo の真の位置と比べて見る。任意の3-2（別の手順書に分けた。2026-11-14）で、同じ台車を ros2_control（`gz_ros2_control` と `ackermann_steering_controller`）で動かし、標準のコントローラが出すオドメトリと自作のものを比べる（実機に移す発展の章の土台になる）。
- **前提**: フェーズ2。
- **完了条件（案）**: 円を1周させたとき、オドメトリの位置と Gazebo の真の位置の差が、走った距離の5%以内に収まる。RViz2 の固定フレームを `odom` にして、台車の動きが表示される（3-1の手順書を作るときに、RViz2 の表示は任意の確かめにし、`tf2_echo odom base_link` で `odom` から `base_link` までの TF が出ることと、ROS 2 を使わないクラスで、積算の位置と円の式の位置の差が 1e-5 m より小さいことを、完了条件にした。2026-11-14）。

### フェーズ4: LiDAR

- **内容**: 4-1で、台車に2Dの LiDAR を載せ、`ros_gz_bridge` で値を ROS 2 に中継し、`ros2 topic` と RViz2 で見る。4-2で、前方の障害物までの距離が決めた値を下回ったら止まり、後退しながら舵を切って向きを変え（切り返し）、障害物を避けて進むノードを書く。4-3（任意）で、横の壁までの距離を一定に保って走る追従を書く。
- **予備の実験**: 専用の GPU が無い PC や、画面なしの起動でも、LiDAR の値が出るか。
- **前提**: フェーズ3。
- **完了条件（案）**: 4-1は、台車の前に置いた壁までの距離が、`LaserScan` の正面の値で、置いた距離と 0.05 m 以内で一致する。4-2は、壁に向かって走らせると、決めた距離の手前で止まり、切り返して壁にぶつからずに向きを変える（台車の外形と壁の距離が0を下回らない）。4-3は、壁との距離の誤差が、走り出してから一定の時間の後に ±0.05 m 以内に収まる。

### フェーズ5: SLAM

- **内容**: `slam_toolbox` をこのフェーズで導入し、フェーズ3のオドメトリとフェーズ4の LiDAR の値で、走らせながら地図を作り、保存する。TF の木（`map → odom → base_link`）と、地図の解像度・範囲の設定を学ぶ。
- **前提**: フェーズ4-1。
- **完了条件（案）**: 決めたワールドを一回りさせ、保存した地図（画像と YAML）で、壁の位置が Gazebo のワールドの壁と、解像度の2倍以内でずれずに重なる。

### フェーズ6: Nav2（ゴール）

- **内容**: 6-1で、Nav2 を導入し、フェーズ5の地図の上で、アッカーマンの台車に合わせた設定（計画器は Smac Hybrid-A\*、追従は Regulated Pure Pursuit の見込み。最小の回転半径・後退を許すか・その場で回らない設定）を書いて起動する。6-2で、RViz2 から目的地を与え、計画された経路と、台車がたどる様子を見る。切り返しが要る目的地も試す。
- **予備の実験**: Jazzy の Nav2 で、この組み合わせが、この教材の台車の曲がれる半径で目的地まで着くか。
- **前提**: フェーズ5。ROS 2 のアクションとライフサイクルは、手順書の中で説明する（親プロジェクトの任意の章は前提にしない）。
- **完了条件（案）**: 決めた3つの目的地に、障害物にぶつからずに、位置の誤差が Nav2 の目的地の許容の範囲（設定した値）以内で着く。計画された経路の曲がり方が、最小の回転半径を下回らない。

### 発展

- **内容**: 深度カメラの値を見て地図や回避に使う、スマートフォン等のアプリから操作する、実機の台車へ移す（シミュレーションで Gazebo が代わりをしていた部分が、実機で何に入れ替わるか）。範囲と形は、フェーズ6を終えてから決める。

## 4. 手順書の方針

書き方の規則は、[`CLAUDE.md`](../CLAUDE.md) の「手順書（`docs/`）の書き方」節にある。要点は次のとおり。

- フェーズごとに1つ（必要なら分割）を、着手の直前に作る。
- コマンドを実行する手順の直後に「期待する結果」（表示の例と読み方）を置く。
- 新しい計算は、先に ROS 2 を使わないクラスで確かめ、その後でノードで包む。
- 図は、SVG を本文に表示し、同じ内容の mermaid 版を折りたたみの中に置く。
- 親プロジェクトの手順書は、GitHub の絶対 URL で参照し、どの節が前提かを README の「読む順番」の「前提」の列に書く。
- 公式の文書の文章は写さず、リンクと自分の言葉による要約にする。
