# 予備の実験の記録

手順書を書く前に、短い予備の実験で確かめたことの記録。教材の本文ではなく、作る側の文書として扱う。実験の生成スクリプトは、Git 管理外の `notes/` に置いている。

## 1. 台車の駆動の方法（2026-11-07）

### 1-1. 目的

Gazebo Harmonic で、アッカーマン式の台車をどう動かすかを決めるため、次の3つの方式で、同じ台車に同じ指令を与え、指令どおりに曲がるかと、学習者が書くものを比べた。

| 方式 | 仕組み |
|---|---|
| A | Gazebo に組み込みのアッカーマンのプラグイン（`gz::sim::systems::AckermannSteering`）。`/model/<名前>/cmd_vel` の `Twist` を受け、舵と車輪を動かす |
| B | 舵の関節を `JointPositionController`、後輪の関節を `JointController`（速さの指令）で個別に動かす。舵の角度と後輪の速さは、外で運動学を計算して与える |
| C | ros2_control（`gz_ros2_control` の `GazeboSimSystem`）と、`ros2_controllers` の `ackermann_steering_controller`。`~/reference` の `TwistStamped` を受ける |

### 1-2. 条件

- 版: Gazebo Sim 8.15.0（`ros-jazzy-gz-sim-vendor`）、`ros-jazzy-gz-ros2-control` 1.2.20、`ros-jazzy-ros2-controllers` 4.42.1
- 台車（この教材で決めた仮の値）: ホイールベース 0.30 m、トレッド 0.24 m、車輪の半径 0.05 m、舵の角度の上限 0.6 rad、本体 0.40×0.20×0.06 m・2.0 kg、車輪 0.1 kg
- 指令: `v`＝0.5 m/s、`ω`＝0.5 rad/s（後車軸の中心の回転半径の理論値は `v/ω`＝1.0 m）
- B に与えた値（自転車モデルを左右に広げた計算）: 内側（左）の舵 atan(L/(R−W/2))＝0.3286 rad、外側（右）の舵 atan(L/(R+W/2))＝0.2617 rad、後輪の回転の速さ 左 ω(R−W/2)/r＝8.8 rad/s・右 ω(R+W/2)/r＝11.2 rad/s
- B の舵の制御の係数: `p_gain` 5、`d_gain` 0.1（舵の関節に力の上限 `effort` 1e6 を書いた）
- 測り方: `OdometryPublisher` で台車の真の位置を 20 Hz で出し、`gz topic -e --json-output` で記録して、最小二乗で円を当てはめた
- 画面なし（`gz sim -s`）で起動し、`GZ_IP=127.0.0.1` と別の `GZ_PARTITION`（C はさらに `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` と別の `ROS_DOMAIN_ID`）で、ほかのシミュレーションと分けた

### 1-3. 結果

| 方式 | 円の半径（真の位置） | 理論値との差 | 平均の速さ・向きの速さ |
|---|---|---|---|
| A | 1.017 m | 1.7% | 0.493 m/s・0.485 rad/s |
| B | 1.025 m | 2.5% | 0.506 m/s・0.493 rad/s |
| C | 1.010 m | 1.0% | 0.506 m/s・0.501 rad/s（走り始めてからの区間） |

- A のプラグインは、自分の推定のオドメトリを `/model/<名前>/odometry` に出す（半径 0.988 m）。最初に、真の位置の `OdometryPublisher` を既定のトピック（同じ名前）のまま足したところ、2つの出し手の値が混ざり、時刻が重なって位置が飛んだ。真の位置のトピックを別の名前（`/car/ground_truth`）にして解決した。**手順書のつまずきやすい点の候補**（同じ名前のトピックに2つの出し手がいても、エラーにはならない）。
- A の最初の実行で、舵の関節に力の上限が無いと「速さの制御が関節の位置の範囲を守らない」という警告が出た。`<limit>` に `<effort>` を書いて消えた。
- C は、コントローラを起動してから、`ros2 topic pub` の指令が効き始めるまで数秒かかった（記録の最初の約7秒は止まっていた）。走り始めてからは指令どおりの速さだった。`robot_state_publisher` は、根のリンクに慣性があると KDL が扱えないという警告を出した（手順書では、根に慣性の無いリンクを置くかを決める）。
- 3つとも、学習計画のフェーズ2-2の完了条件の案（円の半径が `v/ω` と5%以内）を満たした。

### 1-4. 決めたこと（2026-11-08、ユーザー判断）

- **フェーズ1〜3は B で組み立てる**。運動学（フェーズ2）とオドメトリ（フェーズ3）を、計算が見える形で自分で書くため。
- **C は、任意・発展で扱う**。フェーズ3の任意の節で、標準のコントローラのオドメトリと自作のものを比べ、実機に移す発展の章の土台にする（ハードウェアの部分だけを差し替えられるため）。
- A は、フェーズ1の「つまずきやすい点」等で触れる程度にする。

### 1-5. まだ確かめていないこと

- B を ROS 2 からつなぐ部分: `ros_gz_bridge` で、`std_msgs/msg/Float64` の指令を舵と後輪の関節へ中継し、関節の状態（`gz.msgs.Model`）を `sensor_msgs/msg/JointState` として ROS 2 に出す。フェーズ1-2を書く前に確かめる。
- URDF から Gazebo に出したときに、B の関節の制御のプラグインが同じように働くか（今回の A・B は SDF で直接書いた）。
- 舵の制御の係数の決め方と、舵が指令の角度に達するまでの時間（学習計画のフェーズ1-2の完了条件の案は「1秒以内に誤差0.01 rad 以内」）。
