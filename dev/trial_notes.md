## 1. 台車の駆動の方法（2026-11-07）

### 1-1. 目的

Gazebo Harmonic で、アッカーマン式の台車をどう動かすかを決めるため、次の3つの方式で、同じ台車に同じ指令を与え、指令どおりに曲がるかと、学習者が書くものを比べた。

| 方式 | 仕組み |
|---|---|
| A | Gazebo に組み込みのアッカーマンのプラグイン（`gz::sim::systems::AckermannSteering`）。`/model/<名前>/cmd_vel` の `Twist` を受け、舵と車輪を動かす |
| B | 舵の関節を `JointPositionController`、後輪の関節を `JointController`（速さの指令）で個別に動かす。舵の角度と後輪の速さは、外で運動学を計算して与える |
| C | ros2_control（`gz_ros2_control` の `GazeboSimSystem`）と、`ros2_controllers` の `ackermann_steering_controller`。`~/reference` の `TwistStamped` を受ける |

### 1-2. 条件

- 版: Gazebo Sim 8.15.0（`ros-jazzy-gz-sim-vendor`）、`ros-jazzy-gz-ros2-control` 1.2.20、`ros-jazzy-ros2-controllers` 4.42.1
- 台車（この教材で決めた仮の値）: ホイールベース 0.30 m、トレッド 0.24 m、車輪の半径 0.05 m、舵の角度の上限 0.6 rad、本体 0.40×0.20×0.06 m・2.0 kg、車輪 0.1 kg
- 指令: `v`＝0.5 m/s、`ω`＝0.5 rad/s（後車軸の中心の回転半径の理論値は `v/ω`＝1.0 m）
- B に与えた値（自転車モデルを左右に広げた計算）: 内側（左）の舵 atan(L/(R−W/2))＝0.3286 rad、外側（右）の舵 atan(L/(R+W/2))＝0.2617 rad、後輪の回転の速さ 左 ω(R−W/2)/r＝8.8 rad/s・右 ω(R+W/2)/r＝11.2 rad/s
- B の舵の制御の係数: `p_gain` 5、`d_gain` 0.1（舵の関節に力の上限 `effort` 1e6 を書いた）
- 測り方: `OdometryPublisher` で台車の真の位置を 20 Hz で出し、`gz topic -e --json-output` で記録して、最小二乗で円を当てはめた
- 画面なし（`gz sim -s`）で起動し、`GZ_IP=127.0.0.1` と別の `GZ_PARTITION`（C はさらに `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` と別の `ROS_DOMAIN_ID`）で、ほかのシミュレーションと分けた

### 1-3. 結果

| 方式 | 円の半径（真の位置） | 理論値との差 | 平均の速さ・向きの速さ |
|---|---|---|---|
| A | 1.017 m | 1.7% | 0.493 m/s・0.485 rad/s |
| B | 1.025 m | 2.5% | 0.506 m/s・0.493 rad/s |
| C | 1.010 m | 1.0% | 0.506 m/s・0.501 rad/s（走り始めてからの区間） |

- A のプラグインは、自分の推定のオドメトリを `/model/<名前>/odometry` に出す（半径 0.988 m）。最初に、真の位置の `OdometryPublisher` を既定のトピック（同じ名前）のまま足したところ、2つの出し手の値が混ざり、時刻が重なって位置が飛んだ。真の位置のトピックを別の名前（`/car/ground_truth`）にして解決した。**手順書のつまずきやすい点の候補**（同じ名前のトピックに2つの出し手がいても、エラーにはならない）。
- A の最初の実行で、舵の関節に力の上限が無いと「速さの制御が関節の位置の範囲を守らない」という警告が出た。`<limit>` に `<effort>` を書いて消えた。
- C は、コントローラを起動してから、`ros2 topic pub` の指令が効き始めるまで数秒かかった（記録の最初の約7秒は止まっていた）。走り始めてからは指令どおりの速さだった。`robot_state_publisher` は、根のリンクに慣性があると KDL が扱えないという警告を出した（手順書では、根に慣性の無いリンクを置くかを決める）。
- 3つとも、学習計画のフェーズ2-2の完了条件の案（円の半径が `v/ω` と5%以内）を満たした。

### 1-4. 決めたこと（2026-11-08、ユーザー判断）

- **フェーズ1〜3は B で組み立てる**。運動学（フェーズ2）とオドメトリ（フェーズ3）を、計算が見える形で自分で書くため。
- **C は、任意・発展で扱う**。フェーズ3の任意の節で、標準のコントローラのオドメトリと自作のものを比べ、実機に移す発展の章の土台にする（ハードウェアの部分だけを差し替えられるため）。
- A は、フェーズ1の「つまずきやすい点」等で触れる程度にする。

### 1-5. まだ確かめていないこと

- ~~B を ROS 2 からつなぐ部分~~ → 2節で確かめた（2026-11-08）。
- ~~URDF から Gazebo に出したときに、B の関節の制御のプラグインが同じように働くか~~ → 2節で確かめた（2026-11-08）。
- 舵が指令の角度に達するまでの時間（学習計画のフェーズ1-2の完了条件の案は「1秒以内に誤差0.01 rad 以内」）。2節の設定で、フェーズ1-2を書くときに測る。

## 2. 方式 B を URDF と ROS 2 からつなぐ（2026-11-08）

### 2-1. 目的

1節で決めた方式 B を、手順書と同じ形（URDF で書いた台車を Gazebo に出し、ROS 2 のトピックで指令を送る）で動かし、フェーズ1-2を書く前に、つなぎ方と設定を確かめる。

### 2-2. 条件

- 台車（この教材で決めた値。2026-11-08、ユーザー判断）: ホイールベース 0.20 m、トレッド 0.16 m、車輪の半径 0.04 m・幅 0.025 m、舵の角度の上限 0.6 rad（左右の舵の関節それぞれの上限。先に上限に当たるのは内側の舵で、後車軸の中心の最小の回転半径は L/tan 0.6 + W/2 ≒ 0.37 m、そのときの自転車モデルの舵の角度は約 0.49 rad、外側の舵は約 0.42 rad。2026-11-08、ユーザー判断）、本体 0.28×0.12×0.05 m・1.5 kg、車輪 0.08 kg
- URDF の根に、慣性の無いリンク `base_footprint` を置き、固定の関節で `base_link`（車軸の高さ）につないだ。Gazebo のプラグイン（舵の `JointPositionController`、後輪の `JointController`、`JointStatePublisher`、真の位置の `OdometryPublisher`）は、URDF の `<gazebo>` の中に書いた
- 起動: 画面なしの Gazebo（空のワールド）、`robot_state_publisher`（URDF を `robot_description` で渡す）、`ros_gz_sim create`（`-topic robot_description`）、`parameter_bridge`
- 中継: `/car/steer_left`・`/car/steer_right`・`/car/rear_left`・`/car/rear_right` を `std_msgs/msg/Float64` → `gz.msgs.Double`（ROS 2 から Gazebo へ）、`/car/joint_states` を `gz.msgs.Model` → `sensor_msgs/msg/JointState`（Gazebo から ROS 2 へ）、`/clock`
- 指令: `v`＝0.3 m/s、`ω`＝0.6 rad/s（回転半径の理論値 0.5 m）。運動学で計算した舵の角度（内側 0.4444 rad・外側 0.3321 rad）と後輪の回転の速さ（6.3・8.7 rad/s）を、`ros2 topic pub -r 5` で送った

### 2-3. 結果

| 舵の制御の設定 | 舵の角度（左・右） | 円の半径（理論値 0.5 m） | 向きの速さ |
|---|---|---|---|
| 力の指令（`p_gain` 5・`d_gain` 0.1。1節と同じ） | 0.411・0.300 rad（指令より約 0.03 rad 足りない） | 0.524 m（4.8%） | 0.584 rad/s |
| 速さの指令（`use_velocity_commands` true・`p_gain` 10） | 0.4444・0.3321 rad（指令どおり） | 0.510 m（1.9%） | 0.600 rad/s |

- **中継**: 4つの指令は ROS 2 から関節に届き、後輪は指令どおりの速さで回った。`/car/joint_states` は、ROS 2 の側で6つの関節（舵2・前輪2・後輪2）の位置と速さとして受け取れた。前輪（回る関節だけで、駆動していない）は、内側 6.97 rad/s・外側 8.80 rad/s で回った（理論値は約 7.0・9.2 rad/s。外側は少し滑っている）。
- **舵の制御**: 力の指令では、舵の関節の速さが URDF の速さの上限（10 rad/s）に張り付き、角度も届かなかった（小さな慣性の舵のリンクを、力で安定させきれていない）。速さの指令に変えると、角度が指令どおりになった。手順書では、速さの指令の設定を使う。
- **`robot_state_publisher` の警告**: 根を慣性の無い `base_footprint` にしたので、1節の C で出た KDL の警告は出なかった。
- **つまずきやすい点の候補**:
  - `ros2 topic pub` を起動してから指令が届くまで、約3秒かかった（その間、台車は止まっている）。
  - `ros2 topic echo --no-daemon` で型を渡さずに起動すると、相手を見つける前に型を調べて「トピックが出ていない」と失敗した。型（`sensor_msgs/msg/JointState`）を渡すと受け取れた。

### 2-4. 決めたこと

- 台車の寸法は、2-2節の値にする（2026-11-08、ユーザー判断）。
- 舵は `JointPositionController` の速さの指令（`use_velocity_commands`）で動かす（Claude 判断。手順書を書くときに、達するまでの時間を測って確かめる）。
- （2026-11-11 追記）フェーズ1-2を書くときに、Gazebo Sim の `JointPositionController` の実装（gz-sim8）を読んで確かめたところ、`use_velocity_commands` が true のときは `p_gain` 等の PID の係数は使われず、1刻みで指令の角度に着く速さを関節に与えている（実際の速さは、関節の速さの上限で抑えられる）。2-3節の表の「`p_gain` 10」は、結果に効いていない。手順書では、係数の行を書かない。係数を書かない設定で、舵が指令の角度と 0.01 rad 以内に入るまでの時間は、シミュレーションの時刻で 0.06〜0.17 秒だった。

## 3. 画面なしで LiDAR の値が出るか（2026-11-14）

### 3-1. 目的

Gazebo の LiDAR（`gpu_lidar`）は、描画の仕組みで距離を求める。画面を開かない起動（`gz sim -s`）でも値が出るかを、フェーズ4-1を書く前に確かめる（描画に使った仕組み〈GPU の有無〉は記録しておらず、GPU の有無による違いは確かめていない）。

### 3-2. 条件

- フェーズ3-1（と任意のフェーズ3-2）までの手順書から組んだ使い捨てのワークスペースに、フェーズ4-1の下書き（台車の上の LiDAR の部品とセンサ、`Sensors` のシステム〈描画エンジン `ogre2`〉を入れた部屋のワールド、`/scan` の中継）を足した
- LiDAR（この教材で決めた値）: 水平の1周を360本、0.10〜8.0 m、1秒に10回、ノイズの標準偏差 0.005 m。地面から 0.10 m の高さ
- 画面なし（`gz_args:='-r -s'`）で起動し、フェーズ1-2と同じく、`GZ_IP=127.0.0.1`・別の `GZ_PARTITION`・`ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`・別の `ROS_DOMAIN_ID` で、ほかのシミュレーションと分けた

### 3-3. 結果

- `/scan` は、1秒に約10回（`ros2 topic hz` で 9.996）届いた。値は、壁の位置から計算した距離と 0.01 m ほどの差で一致した（正面 2.40 m、左右 1.50 m、後ろ 1.60 m）。
- `frame_id` は、`gz_frame_id` に書いた `lidar_link` になった。`gz_frame_id` は SDF の仕様に無い要素なので、変換のときに「仕様に無い要素を写した」旨の警告が出るが、値には影響しなかった。
- 最初の下書きのワールドで、同じリンクの `collision` と `visual` に同じ名前を付けたところ、`gz sdf -k` が `Non-unique names` のエラーを出した。名前を分けて直した。
- 起動の直後に、型を渡さずに `ros2 topic echo --once /scan` を実行すると、`Could not determine the type for the passed topic` で失敗した。型を渡すと受け取れた。
- 部屋の中で、フェーズ2-2の円（`v`＝0.2、`ω`＝0.4）を走らせたところ、半径は 0.513 m（LiDAR を載せる前の、空のワールドでは 0.512 m）だった。

### 3-4. 決めたこと

- フェーズ4-1は、この設定で書く（Claude 判断。ワールドの形と起動の形は、ユーザー判断。QA 表）。
