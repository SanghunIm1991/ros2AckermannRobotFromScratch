# ROS 2 と Gazebo で、アッカーマン式の台車をゼロから組み立てて自律で走らせる

この教材の構想（なぜ作るか・何を目指すか・どんな技術を選び、なぜそれを選んだか）をまとめた文書。学習の順番と各フェーズの完了条件は [`docs/learning_plan.md`](../docs/learning_plan.md) にある。決めた経緯は [`dev/qa_log.md`](qa_log.md) にある。

作成: 2026-11-07

## 1. 概要・きっかけ

ROS 2 の入門で最初に出会う移動ロボットの多くは、左右の車輪の速さの差で曲がる差動二輪の台車である。その場で向きを変えられるので、速度の指令（前に進む速さ `v` と、向きを変える速さ `ω`）をそのまま左右の車輪の速さに直せて、地図を作る・経路をたどるといった上の層の仕組みも素直に使える。

一方で、身の回りの車の多くは、前輪の向きを変えて曲がる。この形（アッカーマン式）の台車は、その場で回れず、曲がれる半径に下限がある。同じ「`v` と `ω` の指令」を受け取っても、それを舵の角度と後輪の速さに直す計算が要り、指令によっては実現できない（止まったまま向きだけを変える等）。地図の上で経路を計画するときも、切り返しを含む、車が実際に走れる経路を選ぶ必要がある。差動二輪で学んだことの多くはそのまま使えるが、「車らしさ」が効いてくる場所がいくつもある。

市販の教育用ロボットには、アッカーマン式の台車に LiDAR と深度カメラを載せ、ROS 2 で地図を作って自律で走らせるところまでを一通り体験できるものがある。ただ、完成品のロボットでは、多くの部品が最初から組み込まれていて、どこで何が起きているかが見えにくい。この教材は、そうしたロボットの構成を参考にしながら、同じ形の台車を、シミュレーションの中でゼロから一段階ずつ組み立てる。台車の形を URDF で書くところから始め、舵の計算、オドメトリ、センサ、地図、自律の移動と、1つずつ部品を足し、各段階で「動いた」を数値で確かめる。

## 2. 目的と方針

- **目的**: アッカーマン式の台車が、指令を受けてから自律で目的地へ着くまでの仕組みを、部品ごとに自分で組み立てながら理解する。
- **想定する学習者**: ROS 2 に初めて触れる人（C++ か Python のどちらかでプログラムを書いた経験と、Linux の基本的なコマンドの経験を前提にする）。ROS 2 の基礎（ワークスペース・ノード・トピック・launch 等）は、親プロジェクトの [ros2MinimalPhysicalAi](https://github.com/SanghunIm1991/ros2MinimalPhysicalAi) の手順書の節を参照する。
- **シミュレーションで完結させる**: ROS 2 Jazzy と Gazebo Harmonic で、ゴールまでを PC の中で組み立てる。実機への移植は、発展の章で扱う。
- **ゼロから組み立てる**: 台車の模型・舵の計算・オドメトリは、仕組みが見えるように自分で書く。地図を作る（SLAM）・経路を計画してたどる（Nav2）のように、実績のある既存のパッケージがある部分は、それを使い、アッカーマンの台車に合わせる設定を学ぶ。
- **数値で確かめる**: 各フェーズの完了条件は、目で見た印象ではなく、トピックの値・計算の結果など、数値で判定できる形にする。
- **言語**: 一段落するまでは Python だけで書く。
- **扱う車両**: アッカーマン式の台車だけを扱う。ほかの方式の台車（メカナム等）は解説しない（アッカーマンを理解するのに要る範囲の、差動二輪との比較は除く）。

## 3. ゴール

Gazebo の中のアッカーマン式の台車が、LiDAR で作った地図の上で、Nav2 によって目的地まで自律で移動する。曲がれる半径の下限を守った経路（必要なら切り返しを含む）を計画し、その経路をたどって着く。

## 4. 段階のロードマップ

| フェーズ | やること | 主に使うもの |
|---|---|---|
| 0 | 全体の構成を知る（読み物）。アッカーマン式の台車とは何か、どんな部品で自律の移動ができているか | ― |
| 環境構築 | ROS 2 Jazzy と Gazebo Harmonic を用意する | `ros-jazzy-ros-gz` 等 |
| 1 | URDF で台車（前の2輪で舵を切り、後の2輪で進む）を書き、RViz2 と Gazebo に出す | URDF・xacro、`robot_state_publisher`、Gazebo |
| 2 | アッカーマンの運動学: `cmd_vel` の `v`・`ω` から、舵の角度 δ=atan(L·ω/v) と後輪の速さを求め、台車を動かす。最小の回転半径と、実現できない指令の扱い | 自作のノード、Gazebo の関節の制御のプラグイン、`ros_gz_bridge` |
| 3 | 自転車モデルのオドメトリと TF: 後輪の速さと舵の角度から位置と向きを積算し、`odom → base_link` の TF を出す（後に `odom → base_footprint` にした。QA 表 2026-11-14）。任意の節で、ros2_control の標準のコントローラと比べる | 自作のノード、`tf2`、（任意）`ackermann_steering_controller` |
| 4 | LiDAR: 台車に LiDAR を載せ、障害物までの距離を使って、止まる・避ける（切り返しを含む）・壁に沿って追従する | Gazebo の LiDAR、`ros_gz_bridge`、自作のノード |
| 5 | SLAM: 走らせながら地図を作り、保存する | `slam_toolbox`（候補） |
| 6 | Nav2: 作った地図の上で、目的地まで自律で移動する（ゴール） | Nav2（Smac Hybrid-A\*、Regulated Pure Pursuit 等。候補） |
| 発展 | 深度カメラ・アプリとの連携・実機への移植 | 未定 |

## 5. 技術の選定と理由

| 技術 | 選んだもの | 理由 |
|---|---|---|
| OS・ROS 2 | WSL2 + Ubuntu 24.04 + ROS 2 Jazzy | 親プロジェクトの環境をそのまま使える。Jazzy は長期のサポートの版 |
| 物理シミュレータ | Gazebo Harmonic | ROS 2 Jazzy と組み合わせる版で、`ros-jazzy-ros-gz` で入る。親プロジェクトでも使った |
| 台車の駆動 | 舵と後輪の関節を、Gazebo の関節の制御のプラグイン（`JointPositionController`・`JointController`）で個別に動かし、運動学を自作のノードで書く（2026-11-08） | 予備の実験（[`dev/trial_notes.md`](trial_notes.md) の1節）で、Gazebo に組み込みのアッカーマンのプラグイン・関節を個別に動かす形・ros2_control の `ackermann_steering_controller` の3つを比べ、どれも指令どおりの円を描いた。フェーズ2の学びの中心は運動学なので、計算が見える形を選んだ。ros2_control のコントローラは、フェーズ3の任意の節（自作のオドメトリとの比較）と、実機に移す発展の章で扱う |
| SLAM | `slam_toolbox`（候補） | ROS 2 で広く使われ、Nav2 の文書の例でも使われる |
| 経路の計画と追従 | Nav2。計画器は Smac Hybrid-A\*、追従は Regulated Pure Pursuit（候補） | Smac Hybrid-A\* は、曲がれる半径の下限を考えた経路（後退を含む形も選べる）を計画できる。Regulated Pure Pursuit は、アッカーマンの台車でも使える追従の方法として文書に挙げられている。版と設定は、フェーズ6の前に確かめる |
| 言語 | Python | 親プロジェクトと同じ。一段落するまでは Python だけにする |

## 6. 先に確かめること（リスク）

次の点は、動くかがまだ分かっていないので、その段階の手順書を書く前に、短い予備の実験で確かめる。

- **台車の駆動の方法**（フェーズ1・2の前）: Gazebo Harmonic で、アッカーマンの台車をどう動かすか。 → 3つの方式を比べ、関節を個別に動かす形に決めた（2026-11-08。[`dev/trial_notes.md`](trial_notes.md) の1節）。ROS 2 から `ros_gz_bridge` でつなぐ部分も、URDF の台車で確かめた（2026-11-08。同じ文書の2節）。
- **LiDAR の描画**（フェーズ4の前）: Gazebo の LiDAR は描画の仕組みを使う。専用の GPU が無い PC や、画面なしの起動でも値が出るか（ドローンの教材では出た）。
- **Nav2 の設定**（フェーズ6の前）: Jazzy の Nav2 で、Smac Hybrid-A\* と Regulated Pure Pursuit の組み合わせが、この教材の台車の曲がれる半径で目的地まで着くか。切り返しを含めるか。
